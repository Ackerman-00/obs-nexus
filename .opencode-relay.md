### install sweep: two real classes, two harness bugs

Before (`/tmp/opencode/install-sweep/rows.txt`, 15 rows): 7 FAIL. After the
harness fix (`/tmp/opencode/verify6/rows.txt`): only the two genuine defects
remain. The false class was proven, not assumed:

- `helium-browser` TW: `ldd /opt/helium/libqt5_shim.so` → `libQt5Core.so.5 …
  not found`. Chromium's Qt theme shims are dlopen'ed only when Qt exists;
  they cannot break startup. Missing sonames of a *shipped* `.so` are now
  `OPT_MISS` (reported, not fatal); missing sonames of an entry point stay
  fatal.
- `concat`: `libavformat.so.62` reported missing `libavcodec.so.62` — the
  package ships it. NEEDED names the package ships no longer count.
- `heroic-games-launcher` TW: the probe asked for `heroic`, which is the
  *Debian* binary name; the TW RPM is `heroic-games-launcher`. `probes.txt`
  now carries bare package names and the sweep derives the RPM name from the
  spec and the DEB name from the `.dsc` `Binary:` field.
- every verdict now writes `$OUTDIR/<pkg>-<target>.log` (before, a FAIL had no
  diagnosable output at all).

### chrome-sandbox: mechanism proven in a container

`rpm -V` flagged fluxer's sandbox because `%post` promotes it to 4755 after
rpm recorded 0755. Synthetic two-variant build in clean Tumbleweed:

```
== plain  disk=4755 meta=100755 rpmV=[.M.......    /opt/t/chrome-sandbox]
== verify disk=4755 meta=100755 rpmV=[]
```

Nine specs now declare `%verify(not mode)`; heroic + stoat also gained the
`unshare --user` probe they were missing.
