## mixtapes deep-dive (root cause record)

Symptom: `zypper install mixtapes` → "No provider of 'mixtapes' found"; OBS `_result` said `published` but `binarylist` was empty (vacuous pass on a never-built package); latest build log failed at "v8 v130.0.7 … Temporary failure in name resolution".

Root causes (three, all required):
- `%{cargo_install}` re-ran the v8 build script without `RUSTY_V8_ARCHIVE` (only `%build` exported it; env changed ⇒ `rerun-if-env-changed` fired ⇒ re-resolve ⇒ fallback to https URL ⇒ no network on the build host).
- Debian: `dh_autoreconf` and `dh_update_autotools_config` both refresh the vendored `vendor-crates/v8/third_party/icu/source/config.{guess,sub}` (and friends), breaking the `.cargo-checksum.json` the vendored tree relies on.
- Recipe referenced `com.pocuguy.Muse.*` (upstream: `com.pocoguy.Muse.*`) ⇒ `%install`/`debian.rules` died on missing files.

Verification: fresh Tumbleweed container (deps resolve from OSS + repos), `cargo check --release --offline` passes with and without network namespace (`unshare -n`) given the env; the three fixes are each proven by a previously-failing stage now passing (623s v8 stage → cached; 81s checksum stage → passes v8 compile; 583s desktop-file stage → file now found). Full build → `published` ×3, DEB installs on Testing and Sid (`apt-get install mixtapes` → `DEB_OK`), TW `zypper install mixtapes` → pending publish verification (see ledger).
