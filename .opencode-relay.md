## What was actually wrong this run

Nothing in the version table: **all 34 packages were already in sync with
upstream**, so the budget went into recipe correctness rather than version
chasing. Five real defects were found and fixed; two other "problems" turned
out to be non-problems and are recorded as such.

1. **`mixtapes/debian.changelog` head drifted from its `.dsc`** —
   `0+git20261031223600.a50a75d-1` against `.dsc` `Version: 2026.10.31.1+…`.
   Anyone reading `changelog.Debian.gz` saw a version the package never had.
   Fixed, and a CI guard now fails the pipeline if a changelog head stops
   matching its `.dsc` Version.
2. **`faugus-launcher` declared none of the python modules its payload
   imports directly.** `faugus/core.py:173` does
   `from urllib3.util.retry import Retry` and `faugus/utils.py:1912` does
   `import pefile`. No build can catch this — the package built and
   installed happily and would have failed only at runtime. Fixed in both
   recipes; proven by constructing the `Retry` object on a fresh install.
3. **`xdg-desktop-portal-umbriel-git` named the wrong libei module.**
   `meson.build:122` asks for `dependency('libei-1.0', version: '>=1.3')`
   and `option('tests', value: true)` puts it in the default build path, but
   the spec declared `pkgconfig(libeis-1.0)` (the EIS *server* module, which
   nothing in the tree references). `libei-devel` happens to ship both `.pc`
   files, which is why it still built.
4. **`teardown-sweep.py` reported a false missing `BuildRequires: golang`
   for `openchamber`** because its build-tool auditor searched for a bare
   word and matched `xargs chmod go-w`. Now requires command position and
   accepts rpm macro forms, so it also catches `%cargo_build`/`%ninja_build`
   that the old check silently missed.
5. **`teardown-sweep.py` crashed on a warm cache** (`UnboundLocalError:
   fresh_download`) whenever an artifact was already in the workdir — the
   variable was only initialised inside the download branch. Cold runs hid
   it. Fixed and re-run on a warm cache to prove it.

Non-problems, investigated and dismissed with evidence:

* **`hermes-agent-desktop`** tracks its newest *canary tag*
  (`v0.23.1+canary.20261115T064406Z` = commit `d1b46d7`). Upstream `HEAD` is
  8 commits ahead, but the package's documented policy is tag-tracking, so
  this is by design, not staleness. The sweep agrees: "snapshot is ahead of
  HEAD-tracked pin but already contains the newest upstream release".
* **`openclaw` v2026.11.3** still ships zero Linux artifacts (§ issues).
