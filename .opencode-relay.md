- `e183393` — `.github/workflows/update-packages.yml`: the updater job no
  longer dies when a package's `_service` has every service
  `mode="disabled"`. Root cause of the failed pipeline run 40561366413
  (2026-10-27T18:35Z): `matugen/_service` declares all four services
  disabled (its sources are uploaded by `update.sh`), so OBS answers
  `POST .../matugen?cmd=runservice` with `404 <summary>no source service
  defined!</summary>`; `obs_mutate` retried 5×15 s and the job exited 1.
  Reproduced live before the fix:
  `curl -X POST .../matugen?cmd=runservice` → `404 no source service defined!`
  (and the OBS package really does carry `_service`, md5
  `5336573ac739a4a7af5d9441799e076d` == local file). Fix: `obs_mutate`
  returns 2 on that exact 404 (no retry loop), `trigger_build` detects a
  disabled-only `_service` locally and uses `cmd=rebuild`. Verified after
  the fix: extracted the real functions from the workflow into a harness —
  `trigger_build matugen` → `-> Triggering rebuild for: matugen` rc=0;
  forced runservice path → `rc=2` in 1.2 s, then rebuild POST accepted
  (HTTP 2xx, `trigger_build rc=0`). `matugen` TW build afterwards:
  `succeeded` (rev 194).
